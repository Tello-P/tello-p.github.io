MyStrace

A system call tracer for x86_64 Linux, written from scratch in C.

No program opens a file, writes to a screen or allocates memory on its own authority. It asks. MyStrace places itself inside that exchange, halts the traced process at every request, reads the CPU registers directly and transcribes what was asked and what came back.

C11, no external dependencies ptrace(2) · System V AMD64 ABI github.com/Tello-P/strace-in-c

A captured trace

$ mystrace /bin/echo hola
Captured trace
This is the verbatim output of mystrace /bin/echo hola on an x86_64 Linux machine, replayed at the pace it was produced. Select any line to read what the program was asking for at that moment.

Printing four characters costs 63 system calls. The first forty belong to no code that echo ever wrote: they are the dynamic linker locating and mapping the C library before main is reached. Making that visible was the point of the exercise.

The privilege boundary

Two address spaces and one door between them

A process runs in user space under deliberate isolation: it cannot reach the disk, the network, or another process's memory. The kernel can. The only crossing is the syscall instruction, which traps into kernel mode carrying a service number in orig_rax.

I used ptrace(2) to ask the kernel to suspend the traced process precisely at that door — on the way in and on the way out — and to expose its register file to the tracer while it is stopped.

The entry / exit cycle

Every system call stops twice, and the difference matters

Arguments exist only at the first stop; the return value exists only at the second. The tracer therefore runs as a two-state machine, alternating an entry flag so that each stop is interpreted against the correct half of the call. The four stages below follow the control loop across one real openat from the trace above.

RegisterValueMeaning

The ordering of these stages was the hardest defect I resolved. My first control loop read the registers immediately after resuming the tracee, which sampled a register file the kernel had not yet refreshed — producing stale values and duplicated lines. Enforcing resume, wait, validate, then sample eliminated the race entirely.

Reading the tracee's memory

A register holds an address, not a filename

At the openat entry stop, rsi reads 0x7ffd4a2b1e40. On its own that value is meaningless: the path itself lives in another process's address space. PTRACE_PEEKDATA retrieves it, but only one machine word — eight bytes on x86_64 — per call.

I implemented read_data() to issue those word-aligned reads in sequence, reinterpret each returned long as bytes, and terminate as soon as a NUL appears, so that no read runs past the end of the string.

 
Reading the output

Anatomy of a traced line

Syscall: openat (ID: 257) | Result: 0x3
openat — the name resolved through the lookup table I generated in syscall_names_x86_64.h.
257 — the number carried in orig_rax. This is the real identifier; the name is presentation.
0x3 — the value of rax at the exit stop. Here, the file descriptor just allocated.

When rax falls between -1 and -4095 it is not a result but a negated errno, and the line is reported as ERROR (-2). That -2 is ENOENT. It appears on the access call in the trace above — the linker probing a path that does not exist.

Attachment modes

Two ways to acquire a target

Spawning the process

The forked child marks itself with PTRACE_TRACEME and calls execvp. The kernel stops it on the first instruction of the new image, which leaves a window to set PTRACE_O_TRACESYSGOOD before a single system call has run — so nothing is missed.

$ mystrace /bin/ls -la

Attaching to a running process

PTRACE_ATTACH delivers a SIGSTOP to the target, which the tracer must acknowledge through waitpid before entering the loop. On exit, an explicit PTRACE_DETACH restores the process to its original state.

$ mystrace -p 4821
$ mystrace --pid 4821

Signal transparency

Because the tracer intercepts signals destined for the tracee, an unhandled Ctrl+C would terminate the tracer and strand the child. I forward the pending signal through the third argument of PTRACE_SYSCALL, so the traced process observes the interrupt exactly as it would untraced.

Kernel-side permissions

Attaching to a process I did not spawn is additionally governed by the Yama security module. With /proc/sys/kernel/yama/ptrace_scope set to 1 — the default on most distributions — only a direct descendant may be traced, and any other target requires CAP_SYS_PTRACE or sudo.

$ cat /proc/sys/kernel/yama/ptrace_scope
Installation and usage

Getting it running

The tracer has no dependencies beyond a C compiler and the Linux headers. Clone the repository, build it, and either run it in place or install it onto your path.

1

Clone the repository

$ git clone https://github.com/Tello-P/strace-in-c.git
$ cd strace-in-c
2

Build

$ make

Compiles under -Wall -Wextra -Werror and produces the binary at bin/mystrace. That is already runnable — installation is optional.

3

Install onto your path

$ sudo make install

Copies the binary to /usr/local/bin/mystrace, so it can be invoked from anywhere. Override the destination with PREFIX, and reverse the operation with sudo make uninstall.

4

Trace something

# trace a command you launch
$ mystrace /bin/ls -la

# attach to a process already running
$ mystrace -p 4821

# usage summary
$ mystrace --help

Output goes to standard output, so it pipes and redirects like anything else: mystrace /bin/ls | grep openat. Press Ctrl+C at any point to detach cleanly and leave an attached process running.

CommandEffect
mystrace <command> [args]Launches the command under the tracer and reports every system call it makes, from the first instruction of the new image.
mystrace -p <pid>Attaches to a process that is already running. --pid is accepted as the long form.
mystrace -hPrints the usage summary. --help is accepted as the long form.
make rebuildCleans and recompiles from scratch.
make cleanRemoves the object and binary directories.

Requirements: Linux on x86_64, a C11 compiler and make. The register decoding is written against the System V AMD64 ABI, so the tracer is architecture-specific by design — it will build elsewhere, but the register mapping would not apply.

Implementation summary

What the project required

AreaApproach taken
InterceptionPTRACE_SYSCALL driving a stop at both ends of every system call, with PTRACE_O_TRACESYSGOOD marking syscall stops as SIGTRAP|0x80 so they are distinguishable from ordinary signals.
SynchronisationA strict resume → waitpid → validate → PTRACE_GETREGS ordering, resolving a race that had been yielding stale register reads.
DecodingRegister mapping per the System V AMD64 ABI: orig_rax for the identifier, rdi/rsi/rdx/r10/r8/r9 for arguments, rax for the result, with negative-range detection for errno.
Memory accessA word-aligned PTRACE_PEEKDATA reader that reconstructs NUL-terminated buffers from the tracee's address space, sized to PATH_MAX.
Process controlBoth PTRACE_TRACEME/execvp spawning and PTRACE_ATTACH against a live PID, with correct detach semantics and signal forwarding.
ToolchainC11 compiled under -Wall -Wextra -Werror, built by a hand-written Makefile with install and uninstall targets.
