Using this debugger

  1. Load a preset, or build a circuit

    The fastest start is the Presets… menu in the Circuit panel — Bell state is the classic one: a Hadamard puts qubit 0 into superposition, a CNOT entangles it with qubit 1, and the measurement collapses both at once.

    To build your own it goes in three beats. One: click a gate — H, X, Z, C⊕, Oracle, Diffuser or Measure — and it highlights as the selected one. Two: set its arguments just below: a Target qubit, a Control as well for CNOT, or the Basis state the Oracle should mark. Three: press Add to put it at the end.

    Or skip the selectors entirely and drag the gate onto the wire you want it to act on. The wire you drop on becomes the target, and the column decides the position — so a gate can go between two that are already there, not only at the end. A dashed marker and a highlighted wire show exactly where it will land. For CNOT the drop sets the ⊕ target and the control moves out of the way; Oracle and Diffuser span every wire, so only the column matters.

    Gates already on the circuit can be picked up and moved the same way — drag one to another wire or another column. Press and release without moving to remove it.

    On a CNOT, the control dot is its own handle: drag it up or down to re-point the link at a different wire, leaving the target and the position where they are. It refuses to land on its own target, since a qubit cannot control itself.

  2. Set the run options

    Qubits sizes the register (1–4; the state vector doubles each time). Trace chooses the granularity: per gate shows only gate boundaries, per step shows every single inner-loop iteration of the C — slower, but it is where the interesting part is.

    RNG seed is optional. Measurement is genuinely random; give it a seed and the same circuit collapses the same way every time.

  3. Press Compile & run

    The C core executes and streams back a trace of everything it did. The badge next to the title says which build answered — the one bundled into this page, or gcc if you are running the local server, which recompiles the sources on every run.

  4. Scrub through the execution

    Nothing is animated live — the whole run is recorded first, so you can move through it in both directions with the transport bar at the bottom, or with the keyboard: Space play/pause, ← → one event at a time, Home End to jump to either end. The Speed selector goes from 0.5× up to max.

  5. Watch the four panels move together

    Every panel shows the same instant of the same run. The status line at the very bottom narrates it in words — which op is running, which two basis states the current step is combining, what a measurement returned.

State vector
One bar per basis state |00⟩, |01⟩… Blue is a positive amplitude, red a negative one; the highlighted bars are the two the current step is touching. This is the raw Q1.14 data straight out of the register.
Bloch spheres
The reduced state of each qubit on its own. When the arrow shrinks inside the sphere (‖r‖ < 1) that qubit is entangled — it has no definite state of its own any more. Run the Bell preset and watch both arrows collapse inward at the CNOT.
Executing source
The actual C being run, with the current line highlighted. The line numbers come from __LINE__ inside quantum_core.c, so this is a real program counter, not a re-enactment. The dropdown switches between the core, the register, the fixed-point maths and the Arduino build.
Stat tiles
Under the state vector. Norm should stay at 1.0000 and Q1.14 drift is how far it has wandered — the accumulated cost of 14-bit rounding, and the number the whole project is really about. It turns amber past 2%. Per gate is the host timing; the same gate takes 175 µs on an ATmega328P at 16 MHz.
